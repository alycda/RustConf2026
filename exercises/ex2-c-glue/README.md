# Exercise 2: C as the Bridge (30 min)

## Goal

Your Ex 1 solver, callable from C: an `extern "C"` wrapper, a header
generated by cbindgen, and a passing C test harness.

Ex 1 must pass first: `ex_part1` calls your Ex 1 solver, and a `todo!()`
there aborts the harness exactly like a wrong wrapper would.

## Tasks

0. Run `./build-and-test.sh` **before** implementing anything and read
   what happens: `panic in a function that cannot unwind`, then the
   process is gone — no return value, no stack trace for the caller. That
   is the last Key Concept below, seen once on purpose.
1. Implement `ex_part1` in `src/lib.rs` — the TODO walks the four steps
   (null check → `CStr` → UTF-8 validation → call your solver).
2. Fill in the example input and expected answer in `tests/c/test_glue.c`.
3. `./build-and-test.sh` — it builds the cdylib, generates
   `include/ex2_c_glue.h`, compiles the harness, and runs it.
4. **Read the generated header.** One minute, out loud if you like. Knowing
   what cbindgen produced is the difference between using it and trusting it.
5. If time allows: `ex_part2`.

## Key Concepts

- `#[no_mangle] pub unsafe extern "C" fn` — the full incantation and why
  each piece exists (symbol name, visibility, caller contract, calling
  convention).
- The null and UTF-8 checks are not paranoia — they're the *contract*. C
  will hand you anything.
- In-band error values (`-1`) vs richer conventions — we debrief this in
  Module 4.
- Panics must not cross the boundary: Rust ≥1.81 aborts the process if they
  do. Step 0 is that, watched once on purpose.
