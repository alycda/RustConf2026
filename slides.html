01 — Why is this hard?

An FFI signature is a treaty between two runtimes that disagree about memory, types, errors, and encoding — and neither side can enforce it.

01 — Why is this hard?

Four disagreements

01

Memory

Who allocates, who frees, who is sure?

02

Types

Rust's String doesn't exist over there. Neither does Result.

03

Errors

Panics don't cross. Exceptions don't cross. Integers cross.

04

Encoding

“it's just a string”

01 — Why is this hard?

“It's just a string”

  • rustUTF-8; CString refuses interior NUL — validation at the boundary
  • cbytes + NUL terminator, no promises whatsoever
  • swiftUTF-8 inside (since Swift 5); the NSString bridge is UTF-16 — hidden work
  • jvmmodified UTF-8 via JNI. Not quite UTF-8. Really.
  • pythonunicode object; you .encode() first — explicit, honest
  • dartUTF-16 code units; toNativeUtf8() — and you free it

02 — C as the bridge · live

Rust → header → C caller

Four commands, one boundary — from exercises/ex2-c-glue.

cargo build                              # Rust → shared library
cbindgen --output include/ex2_c_glue.h   # Rust → C header (read it!)
cc tests/c/test_glue.c -L../target/debug -lex2_c_glue \

A panic crossing extern "C" aborts the process (Rust ≥ 1.81). No stack
            trace for the caller. Just gone.

null check → CStr → UTF-8 check → call → in-band error value

        is about your puzzle, not about C.

      12:00 — Debrief · part two
      
Who actually read the header?

      
One header, four treaties — enforced, consumed, copied, remembered.

      
    
        
  • swiftclang compiles against it. Drift is a compile error.
            Enforced.
    • 
        
  • python / cffireads it at runtime, derives every call. Can't drift —
            but trusts it blind. Consumed.
    • 
        
  • dart / ffinever opens it. Typedefs hand-transcribed, header as reference.
            Copied.
    • 
        
  • kotlin / jnanever opens it either. Interface hand-mapped, kept in sync by
            care. Remembered.
    • 
      

      
Only one track keeps the guarantee your Ex 2 C harness had: #include, then a
        compiler.
